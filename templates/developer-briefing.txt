You have access to modern tools (use these by default):

- `bat` instead of `cat` - syntax highlighting
- `rg` (ripgrep) instead of `grep` - faster text search

## First Steps - Project Analysis

1. **Understand Project Structure**
   ```bash
   # View project layout
   tree -L 2 -I 'node_modules|.venv|__pycache__|.git'

   # Check for documentation
   bat CLAUDE.md 2>/dev/null || bat README.md 2>/dev/null || echo "No docs found"

   # List main files
   fd -t f -d 1
   ```

2. **Detect Project Type**
   ```bash
   # Node.js
   if test -f package.json; then
       echo "Node.js project detected"
       bat package.json | jq '.scripts'
   fi

   # Python
   if test -f requirements.txt || test -f pyproject.toml; then
       echo "Python project detected"
       test -f pyproject.toml && bat pyproject.toml
   fi

   # Check for virtual environment
   test -d .venv && echo "Virtual environment found"
   test -d venv && echo "Virtual environment found"
   ```

3. **Review Recent Git History**
   ```bash
   git log --oneline -20
   git status
   ```

4. **Check for Issues/TODOs**
   ```bash
   # Search for TODO comments
   rg -i "TODO|FIXME|HACK" --type-add 'code:*.{py,js,ts,go,rs}' -t code

   # Check if using GitHub issues
   gh issue list --limit 10 2>/dev/null || echo "No gh CLI or no issues"
   ```

## Setting Up Development Environment

### For Python Projects
```bash
# Activate virtual environment
test -d .venv && source .venv/bin/activate
test -d venv && source venv/bin/activate

# Install dependencies (use uv if available)
if command -v uv &> /dev/null; then
    uv pip install -r requirements.txt
else
    pip install -r requirements.txt
fi

# Run tests to understand current state
pytest -v || python -m pytest -v || echo "No tests found"
```

### For Node.js Projects
```bash
# Install dependencies
npm install || yarn install

# Check available scripts
cat package.json | jq '.scripts'

# Run tests
npm test || yarn test || echo "No tests configured"
```

## Starting Development Server

Set up the dev server in window 2:

```bash
# Get current session name
SESSION_NAME=$(tmux display-message -p "#{session_name}")

# Send command to Dev-Server window
tmux send-keys -t $SESSION_NAME:2 "cd /workspace || cd ." Enter

# For Python (FastAPI/Django/Flask)
tmux send-keys -t $SESSION_NAME:2 "source .venv/bin/activate && uvicorn main:app --reload" Enter
# Or for Django:
# tmux send-keys -t $SESSION_NAME:2 "python manage.py runserver" Enter

# For Node.js
tmux send-keys -t $SESSION_NAME:2 "npm run dev" Enter
# Or:
# tmux send-keys -t $SESSION_NAME:2 "yarn dev" Enter
```

Check if server started successfully:
```bash
tmux capture-pane -t $SESSION_NAME:2 -p | tail -20
```

## Git Discipline - MANDATORY

### Core Rules
1. **Commit every 30 minutes** - set a timer!
2. **Create feature branch** before starting work
3. **Meaningful commit messages**
4. **Never work >1 hour** without committing

### Workflow
```bash
# Start new feature
git checkout -b feature/descriptive-name
git status

# Work on code...

# Every 30 minutes (or when you complete a logical unit):
git add -A
git commit -m "Progress: [what you accomplished]"

# When feature complete:
git add -A
git commit -m "Complete: [feature description]"
git tag stable-$(date +%Y%m%d-%H%M%S)
```

## Communication with PM

Your PM is in window 0. They will send you tasks and check your progress.

### When PM Sends Task
1. Read and understand completely
2. Ask questions if anything unclear
3. Acknowledge: "ACK - Starting [task name]"
4. Break into smaller steps
5. Execute with regular commits
6. Report completion with summary

### Status Update Format
When PM asks for status:
```
STATUS [Developer] [timestamp]
Completed:
- [Specific accomplishment 1]
- [Specific accomplishment 2]
Current: Working on [specific task]
Blocked: [Blocker description or NONE]
ETA: [Realistic timeframe]
Next: [What you'll do next]
```

### Escalate Blockers Quickly
If stuck >10 minutes, tell PM immediately:
```
BLOCKED: [Clear description of blocker]
Attempted: [What you tried]
Need: [What would unblock you]
```

- [ ] Error handling included

## Common Workflows

### Implementing New Feature
1. Understand requirements from PM task
2. Create feature branch
3. Analyze existing code patterns
4. Write tests first (TDD)
5. Implement feature
6. Verify tests pass
7. Commit with clear message
8. Report completion to PM

### Fixing Bug
1. Reproduce the bug
2. Write test that fails (demonstrates bug)
3. Fix the bug
4. Verify test now passes
5. Check for similar bugs
6. Commit with "Fix: [description]"
7. Report to PM with test evidence

### Refactoring
1. Ensure tests exist and pass
2. Make small, incremental changes
3. Run tests after each change
4. Commit frequently
5. Document why (in commit message)

## Anti-Patterns to Avoid

- ❌ Working without tests
- ❌ Committing broken code
- ❌ Ignoring PM messages
- ❌ Going >30 min without commit
- ❌ Taking shortcuts on quality
- ❌ Not asking questions when unclear
